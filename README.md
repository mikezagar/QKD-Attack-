# QKD-Attack-

## Abstract
Quantum Key Distribution (QKD) is a method of secure and efficient communication between two parties, widely considered to be an unbreachable channel using quantum mechanical laws. Many studies have been done in the field of Quantum Hacking to break this security in the hope to reveal any potential shortcomings of the algorithm to push members to think of novel ideas. This paper utilises the Manipulate and Observe attack which partially intercepts the data exchanged during its quantum phase to remain hidden throughout the QKD process and observes parity announcements throughout error correction. The implementation of this attack simulated on the BB84 protocol which utilises Cascade as a method of error correction. This simulation has yielded a 34% information gain by the eavesdropper for this channel with a key size of 450,000 bits. Where it is seen that as the QBER increases in the system, then the security of the channel decreases to the point where the channel is no longer secure before the threshold can be reached. We can therefore see that the simulated attack implemented in this project has shown that the simulated channel detailed in this work has the potential to intercept more data compared to the approximate performance detailed by the Shor – Preskill approximation. Which therefore indicates that the Manipulate and Observe attack breaks the security of QKD communication. The results obtained from this paper form a proof of concept and provides evidence that QKD is no longer secure against attacks, by detailing the lack of security against the Manipulate and Observe attack. Where this attack though performing sub optimally, still has the capability to intercept 34% of the secret key, where further advancements in the development of this attack can expose the key even further. The results obtained from this project serves as motivation for researchers in Post-Quantum Security to provide novel ideas towards more secure methods of communication.

## Cascade
Cascade builds off the BINARY algorithm by proceeding in several passes throughout the duration of its run time, with the number of passes chosen by Alice and Bob before execution. The number of passes is determined through the amount of error each string of bits is exposed to with some probability. Once the first pass of Cascade is complete, running through the BINARY protocol without any alterations, will lead to an even number of errors within each block. The algorithm cannot feasibly detect any remaining errors in this pass, thus the algorithm moves onto the next pass [32]. The following passes then shuffle the indices of the key around to prevent any two errors remaining coupled and potentially letting errors through without correction. With the shuffled indices, Cascade runs through the BINARY protocol again carefully correcting errors, whilst also ensuring no previous blocks change their parities and undoing past parity corrections in the process of correcting an error. The inherent backtracking of this algorithm has the potential to lead into severe runtimes errors if handled incorrectly. Therefore, to offset this the algorithm was designed to flag any repeat parity flips on the same index, whilst also storing the blocks that need correcting in a queued data structure. The queue data structure handles blocks in a First-In First-Out (FIFO) order, allowing for a sequential handling of block corrections. This is then done until all the errors are corrected and a reduced QBER can be calculated.

## Manipulate and Observe Attack
With the construction of the BB84 protocol complete, and the introduction of Partial Intercept and Resend attack which this is based on, this attack now needs to be designed and introduced into the system. The proposed attack is a method of interception with the purpose of remaining undetected and observing enough data throughout the BB84 protocol to piece together Alice’s key. As mentioned previously, this attack implements the commonly used Partial Intercept and Resend attack to gain information from the initial quantum communication channel; this is the active phase of the attack. The rest of the attack is known as the passive phase, where throughout the error-correction algorithms simulated using Cascade, Eve simply observes the parities found, eliminating key candidates generated and narrowing down her search space.

### Passive Phase
The secret key shared by both Alice and Bob is a binary bit string, with n being the total number of bits. With this there are then 2𝑛 potential candidates of the key that Eve is trying to reconstruct, with each bit discovered by Eve halving the total number of candidates. Where the data leaked through the process of error reconciliation can drastically reduce Eve’s search space by restraining the number of potential candidates in the secret key. Since the Cascade algorithm computes the parity of a specific set of sub-blocks, this will impose a parity condition on Eve’s search space, where she knows the set of indices being checked and the parity of each set. This will in turn allow her to eliminate elements of her candidate key, narrowing down the search space for each pass. Once Cascade has concluded, Eve will construct a set of remaining candidates and launch a brute force filtering method to eliminate the candidates to a single key candidate.
Due to the nature of the large key length, it isn’t feasible to be handling key sizes of upwards of 450,000 bits when running the passive phase of the attack. To offset this issue, we opted for a logarithmic tracking of the candidates rather than explicitly storing the candidates in a dataset. In doing this, we track the log2 of the candidate count allowing us to implement a larger bit string rather than potentially needing to limit the number of candidates needed to evaluate in the sake of preserving runtime. Another consequence of this large key length is the execution of the brute force filtering method, which would lead to a computationally expensive attack that would prove infeasible. The implementation of the passive phase therefore, excluded this brute force filtering.

As mentioned before, this phase of the attack utilises the Partial Intercept and Resend attack then throughout their public key reconciliation, Eve can intercept the choice of bases and sift through her initial key, determining the indices she knows with certainty. This is depicted in greater detail in Figure 6.
As discussed previously the Partial Intercept and Resend attack is built around remaining under the threshold limit and thus requires a QBER given by the following formula,

$ p_{max} = \rho / 4 $

where \rho being the interception probability and 𝑝_𝑚𝑎𝑥 is the maximum allowed QBER generated from interception. Since the maximally tolerated QBER is typically set to 11%, thus an appropriate interception probability is around 40% which would lie safely below the threshold.

To answer this, we need to see the relationship between the information gained and the interception probability to verify the feasibility. Where we can calculate that the maximum interception probability 𝜌𝑚𝑎𝑥=44% with a QBER threshold of 11%. What this tells us is in a key-length of approximately 450,000 bits, Eve can intercept 34% of these bits which is a substantial amount of information potentially leaked throughout this communication. It must be noted that the passive phase of the Manipulate and Observe attack, includes a brute force filtering method, filtering through the remaining block candidates in parallel with each other. In the scale of this paper, exchanging 450,000 bits, would leave approximately 10,000 candidates to be sifted through. Where with a dataset this large the brute force method proves to be too computationally expensive, even with the vast computational power of the AIRE computer cluster. Thus, for the purpose of this project, it has been decided to exclude this step from the passive phase. However, the results obtained from this shows that at the maximum interception rate can constitute this as a substantial security breach exceeding the Partial Intercept and Resend attack’s information gain.
